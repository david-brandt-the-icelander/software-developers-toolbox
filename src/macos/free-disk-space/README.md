# free-disk-space

`free-disk-space` — single Rust binary for reclaiming space on macOS/APFS.

Build: `cargo build --release -p free-disk-space` in `src/macos`, or download a release: `https://icelander.net/downloads/zazzle/latest/zazzle-macos-universal.tar.gz` (with a `.sha256` next to it; also on the GitHub releases). Or with Homebrew: `brew install zazzcat/z/zazzle` (installs every tool here). A browser download of an unsigned build makes macOS say it "could not verify" the binary; run `xattr -d com.apple.quarantine shell-tools fix-network free-disk-space` after unpacking.

```bash
zazzle free-disk-space clean all                 # dry run: caches, downloads, trash, dev artifacts, docker
zazzle free-disk-space clean caches dev --apply  # really do it (also: brew, xcode targets)
zazzle free-disk-space scan --root ~ --min-size 5M  # resumable scan for compression, duplicates and cleanup (Ctrl-C safe; `new` is an alias)
free-disk-space resume
zazzle free-disk-space status
free-disk-space list --top 30
zazzle free-disk-space dedupe                    # dry run: identical same-named files to clone
zazzle free-disk-space dedupe --sample 5 --apply # verify on a few duplicates, then drop --sample
zazzle free-disk-space compress --sample 5       # verify on a few files first
zazzle free-disk-space compress --limit 20G --yes
zazzle free-disk-space repair                    # dry run: files falsely claimed to be compressed
zazzle free-disk-space repair --apply            # reset, record or really compress them
zazzle free-disk-space daemon install            # background: login item, 30G threshold, every 15m; cleans, then dedupes and compresses
```

- **Scan** records every processed directory in SQLite (`~/.local/state/free-disk-space/scan.sqlite3`, or `$FDS_STATE`), so `resume` continues where it stopped. Candidates are large, inactive, uncompressed, single-link files whose sampled compressibility is high; archives, media, databases, VM disks, credentials and app bundles are skipped.
- **Dedupe** uses the full path of every file the scan saw (recorded in the same state file). Files sharing a leaf name (with extension) and size, of which at least one is writable, are SHA-256 hashed; identical ones on the same volume are replaced by APFS copy-on-write clones (`clonefile`, like `cp -c`) of one kept copy. Each replaced file keeps its own metadata, not the kept copy's: mode, owner and group, BSD flags (such as hidden), ACL, access, modification and creation times, and every extended attribute with its value (Finder tags, quarantine, provenance), while attributes only the kept copy had are removed. Where macOS refuses to set an attribute such as `com.apple.provenance` directly, `/usr/bin/xattr` sets it. All of it is checked before the swap, and a clone that differs in any of it is not swapped in; only the inode number and how the shared data is stored change. A dry run unless `--apply`. System files (not owned by you, owned by root, or under `/Library`, `/Applications`, `/private` and the like) are only touched with `--include-system`. Hard-linked, open, compressed, immutable and iCloud-placeholder files are never replaced. Run it before `compress`, which makes files ineligible. Before choosing which copy to clone from, it clones each identical copy into the temp folder once and deletes the clone: macOS privacy protection can refuse to let a process clone a file it lets it read (such as one in `~/Documents`), and a copy that can't be cloned is reported as skipped and is neither cloned from nor replaced. A failed clone names the copy it cloned from.
- **Compress** writes APFS transparent compression itself (LZFSE, on all cores) with the `lempel-ziv-finite-state-entropy-compression` library compiled into the binary (vendored in `src/macos/lempel-ziv-finite-state-entropy-compression`, MPL-2.0): it clones the file to a temp file beside it (`clonefile`, keeping mode, owner, flags, xattrs and times), puts the compressed form on the clone, verifies flags (the original's other BSD flags too), size, mode/owner, every extended attribute's value, the ACL, SHA-256 and allocated-size gain, sets the original's access, modification and creation times on it and reads them back, then atomically swaps it in. Open, recently changed, flagged or hard-linked files are skipped, and so are files with a real resource fork, because compression stores its data in that attribute; a file that fails verification is left as it was, printed as `NOT COMPRESSIBLE` with the reason and recorded as `failed`, so later runs skip it, and the run carries on; the summary groups these files by reason (`list --status failed` shows them). A copy may carry `free-disk-space`'s `com.apple.provenance` instead of the original's (macOS stamps a new file with the app that made it and may not let it be changed back): that one attribute is left out of the check, every other one must match. Files without a provenance, or with an empty one, are usually Apple's or the system's; `compress`, `repair` and `dedupe` leave them alone unless `--include-no-provenance` is given. Files that failed only because of the provenance go back in the queue on the next run, and `--retry-failed` (compress and dedupe) puts every earlier failure back. After compressing, it sets any attribute value the copy got differently back to the original's (macOS stamps a clone with the `com.apple.provenance` of the process that made it), through Apple's `/usr/bin/xattr` when macOS refuses the direct call; if a value still differs, the file fails with a note naming the attribute and why (refused, with the error, or set and then changed again). Reports verified savings separately from the free-space delta. It first compresses a test file the same way and stops unless it reads back as compressed and unchanged. (`ditto --hfsCompression`, used before, reports success but writes uncompressed copies on macOS 26/27.)
- **Repair** checks every file the scan saw for a false compression claim; a dry run unless `--apply`. A file the state file records as compressed that is not is reset to pending for the next `compress`. A file flagged compressed whose `com.apple.decmpfs` attribute is missing or invalid, whose header size differs from its size, or that cannot be read back is reported and recorded as `broken` (`list --status broken`): nothing can be recovered from it, so restore it from a backup. A flagged file whose compressed form takes at least as many 4 KiB disk blocks as the plain file would is decompressed: rewritten as a plain copy with its mode, group, flags (without the compressed flag), extended attributes and ACL, verified and swapped in like `compress` does (same age, link, open-file and free-space checks), and recorded as skipped so `compress` leaves it alone. Small files compressed inside their attribute take no block, so they save space and are left alone.
- **Daemon** (`zazzle free-disk-space daemon install`) registers a launchd login item (`~/Library/LaunchAgents/local.free-disk-space.plist`, log in `~/Library/Logs/free-disk-space.log`) that runs `daemon run` now and at every login. Every `--cadence` (default `15m`; `90s`, `2h` also work) it compares free space on the data volume with `--threshold` (default `30G`; a percentage such as `10%` also works) and, when below, runs `clean --apply` on `--targets` (default `caches dev`; add `trash`, `docker`, ... explicitly). The cadence counts awake time only: the clock stops while the Mac sleeps, the process never schedules a wake, and checks are skipped while the display is asleep (maintenance wakes). `daemon status` and `daemon uninstall` manage it; `daemon run` runs in the foreground. Reinstall to change settings; the plist stores the path of the binary you installed from, so reinstall after moving or upgrading it. When cleaning leaves free space still below the threshold, it also brings the scan up to date (resuming an unfinished one, or rescanning when the last finished more than 7 days ago), runs `dedupe --apply`, then `compress --yes --limit` with the amount still missing; each runs as its own process and is logged. `--clean-only` keeps it to cleaning.
- **Clean** is a dry run unless `--apply`. Dev artifacts need a manifest/lockfile, git-ignored and untracked contents, no modification today (Atlantic/Reykjavik), and no running process using them; eligibility is rechecked before deletion. Docker is only touched if already running (never started); containers and volumes are kept.

Caveats: unit-tested in CI on macOS and Linux; smoke-tested on Linux only for the scan/dry-run paths; `compress`, `dedupe --apply`, Finder trash, and Docker steps are untested on a real Mac. APFS clones (shared blocks) can't be detected (so `dedupe` savings are an upper bound), so compare the free-space delta on a `--sample` run before going broad.
