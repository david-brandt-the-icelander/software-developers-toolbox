# zazzle agent

`zazzle agent get-rules ...` or `zazzle get-rules ...` (MCP `zazzle_get_rules`) is answered by daemon, which remembers per session what it sent; the `ai-agent-rules` binary runs the same lister without that memory. Docs: `src/macos/ai-agent-rules/README.md`.

## get-rules
- `zazzle agent get-rules PATH... [--purpose NAME]... [--name-only] [--skill-bodies] [--again]` prints the rules and skills for the home folder and every folder from `/` down to PATH (a file or folder that exists; else exit 66). Several paths print their union, each file once.
- In a session, files and segments already sent (by get-rules, or after a read or edit) are left out and named in one `-- already delivered` line; a changed file, a new purpose's segments, or a reset after compaction are sent again. `--again` sends everything. Universal rules stay in force even when not repeated.
- Each rule is a `==> rule FILE <==` header and its text; each file a rule imports (`@path`) follows it as `==> import FILE <==`; each skill is a `==> skill FILE <==` header and its description only. `--skill-bodies` prints whole skills; `--name-only` prints just `rule FILE`, `import FILE` or `skill FILE` lines. `.claude/rules` files with `paths:` globs appear only for matching paths.
- Order is farthest first, closest last; the closest file wins, and the user's chat overrides all files. A `CLAUDE.md` that only imports `@AGENTS.md` is not repeated.
- Read a skill's file only when its description fits the task.
- `--purpose NAME` (repeatable) keeps only files and segments marked for NAME with a marker on its own line or after a comment opener (`<!-- #zazzle-purpose:NAME -->`, or a `-begin:NAME` / `-end:NAME` pair); unmarked files stay. A segment prints as `FILE:A-B` and only those lines.
- After editing rule or skill files, run `zazzle ai-agent-rules check [PATH]`: one `FILE:LINE: message` per `@file` import that points nowhere, `paths:` glob that matches no file, or skill front matter missing `name`/`description` or naming another folder; exit 1 when there are problems, `--json` for an array.
- To see why a rule or skill applies to a file or not (folder level, matching or missing `paths:` glob, importing file, purpose), run `zazzle ai-agent-rules explain PATH [--purpose NAME]... [--json]`.

## Local models: llm, chat and prompt
- `zazzle agent prompt [--model NAME] [--effort low|medium|high] [--system TEXT] [--max-tokens N] TEXT..` prints a local model's answer; `-` in TEXT (or no TEXT) reads standard input: `git diff | zazzle agent prompt "Review this diff:" -`. It adds the message to this terminal's conversation (the flags apply to that message only), so a follow-up prompt sees the earlier ones; `zazzle agent prompt /clear` forgets them.
- `zazzle agent chat` is the same conversation, interactive, for the user: `/effort`, `/model`, `/clear`, `/new`, `/status`, `/quit`; Ctrl+K starts a new conversation, Ctrl+C leaves. the daemon keeps the model loaded between messages, so only the first one waits for it to load.
- `zazzle agent llm` lists the models (size, downloaded or not, default); `--model NAME [--effort E]` downloads one and makes it the default; `--remove NAME` deletes it. Docs: `src/macos/ai-agent/README.md`.
- `zazzle ai-agent status [--json] [--verify]` reports the default model and effort, downloaded models (checked by size, by SHA-256 with `--verify`), partial downloads and disk use; exit 1 (`"ok": false`) when the default is missing or a model is corrupt. `zazzle ai-agent prune` lists every model but the default, stale partial downloads and orphaned locks with the space they take; `--apply` deletes them (models in use are skipped). Ask the user before `--apply`.
- The first use downloads `ai-agent` and the model (gigabytes): tell the user before choosing a model that is not downloaded yet.
- The effort is low (no thinking) unless the chat's `/effort` or `--effort` says otherwise; thinking is never printed.
- Exit 3 means the token limit cut the answer short: raise `--max-tokens` or lower `--effort`.
- To spend fewer tokens on output you need only part of (an API response, a log, a test run), add `--llm 'INSTRUCTION'` to the zazzle command (`zazzle run --llm 'Only the failing tests' -- cargo test`; MCP: `llm` on reading tools). The answer is the local model's and may drop detail: rerun without `--llm` when exact text matters.
- Before a task in an unfamiliar repository, `zazzle brief 'WHAT YOU WILL DO' --path PATH --purpose NAME` (MCP `zazzle_brief`) is the rule read: do not read AGENTS.md, CLAUDE.md or skill files yourself first, since the brief would send them again. The paths and purposes decide what applies before the model is asked: every rule section that applies is printed verbatim, and the local model only ranks the skills. A budget (`--budget`, default 8000 tokens) drops whole skills, never part of a section or a rule. Sections this session already received (from `get-rules`, a read's notes or an earlier brief) are named, not repeated; `zazzle get-rules PATH --again` resends everything.
- A question that needs evidence from several files: `zazzle investigate 'QUESTION' --path SCOPE --symbol NAME` (MCP `zazzle_investigate`). Seed it with the real entry point (the endpoint's handler, found with `zazzle find-symbol` or `zazzle refs` first) and give one `--path` per layer the call crosses (facade, service, handoff to the next system) plus their tests. The local model follows read-only lookups inside the scope, starting from the symbols, and answers. Each `path:line` it cites comes back checked against the file and quoted; bad citations and unknowns are listed.
  - A symbol not found in the scope comes back with real candidate files and symbols; if no symbol exists and nothing resembles one, the result is "no evidence" and the model is not asked.
  - A lookup the model already made is not run again, and a file that does not exist comes back with real ones that resemble it.
  - It returns one result within about 90 s (`--seconds`, MCP `seconds`), waiting for the local model included. Call it directly as a tool and wait; never from a script that yields, sleeps or polls.
  - PARTIAL: no finding could be verified; ranked verbatim excerpts of the evidence follow, with the lookups that found nothing, so read those instead of repeating the lookups. INCOMPLETE: the run stopped early. The claims are the model's, so verify what you act on.
  - For a question with parts of different difficulty, add `--adaptive` (MCP `adaptive`): zazzle plans it, runs each part on the cheapest agent and effort in `--agents` (local models, `claude:MODEL`, `codex:MODEL`, `@EFFORT`) that will do it, and escalates a part that is not settled with what it established. Each part reports its confidence; `needs the user` lines are decisions or access only the user can give, so ask them. `--json` gives the structured result.
  - `--orchestrator M [--orchestrator-effort E]` (MCP `orchestrator`, `orchestrator_effort`; or `ZAZZLE_ORCHESTRATOR` and `ZAZZLE_ORCHESTRATOR_EFFORT` for everything) lets an external model (`claude:MODEL`, `codex:MODEL`) plan, combine and summarize instead of the local ladder, and do the local model's other housekeeping too (`zazzle flow` writer, lint fixer, test author, conflict resolver, CI triager and review briefs; `zazzle brief` skill ranking; `--llm` post-processing, whose output then leaves the machine); the usage lines and `--json` `usage.orchestrator` / `usage.executors` keep its tokens apart from the execution agents'. Every adaptive run, flow command, `--llm` and brief call is also logged, without any text, to `~/.zazzle/orchestration.jsonl` (`ZAZZLE_ORCHESTRATION_LOG`) for analysis.
  - `--review-model M` has another agent judge the results and each finding; `--benchmark-model M` also answers with that agent alone and compares findings, time, tokens and cost. Each adds up to `--seconds` to the call, so raise the time limit only when the client's tool timeout allows it.
- Use the local model where it saves something. Read short results (find-symbol, refs, outline, a range) yourself; `--llm` passes output under ~400 tokens through unchanged. Don't spend a local call early, or just because one is expected.
- Rules reach you apart from the source. A read's rules go to standard error on the command line, so `zazzle read FILE | zazzle agent prompt 'Summarize:' -` sends the model only the source, while you still get the rules you must follow.
- `zazzle prompt TEXT` (MCP `zazzle_prompt`) asks the local model directly. These never download a model: if one is missing, ask the user to run `zazzle agent llm --model NAME`.
